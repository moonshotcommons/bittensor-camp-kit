# 环境安装与版本说明（`btcli` 11.x / `bittensor` 11.x）

> **版本基线**：本课程与配套代码库全面对齐 **`bittensor` v11.x**（含 Python SDK 与 `btcli` 11.x）。以下安装步骤与新旧命令对照整理自官方 [Migration Guide](https://www.bittensor.com/docs/migration)。

## 1. 先弄清楚要装哪个包

现在有两个包都会安装 `btcli` 命令，**只装 `bittensor`**：

| 包名 | 装出来的 btcli | 说明 |
|---|---|---|
| `bittensor` | **11.x** | 当前版本。一个包里同时有 Python SDK、`btcli` 命令和钱包功能 |
| `bittensor-cli` | 9.x | 旧的独立命令行包，已被 `bittensor` 11 取代。怎么升级都只到 9.x |

很多旧教程写的是 `pip install bittensor-cli`，照着装就会得到 9.x，后面课程里的命令会对不上。

另外，`bittensor-wallet` 这个包也不用再装了，钱包功能已经包含在 `bittensor` 里。

## 2. 新电脑安装

**系统**：macOS 或 Linux，Python 3.10–3.14。Windows 不支持原生安装，请先装 WSL 2，在 WSL 里操作。

推荐用 [uv](https://docs.astral.sh/uv/)。二选一：

**方式 A：全局安装命令行（只想用 btcli）**

```bash
uv tool install bittensor
```

**方式 B：在项目虚拟环境里安装（第二周跑代码用这种）**

```bash
uv venv --python 3.12
source .venv/bin/activate
uv pip install bittensor
```

不用 uv 的话，在虚拟环境里执行 `pip install bittensor` 也可以。

## 3. 检查是否装对

```bash
btcli --version
```

应显示 `11.x`。如果显示 `9.x`，说明装到的是旧包，按第 4 节处理。

再查一次主网数据，确认能连上链：

```bash
btcli -n finney query burn --netuid 64      # 64 号子网当前的注册价格
btcli -n finney subnets show 64             # 子网概况：tempo、注册价格、席位
```

## 4. 已经装过旧版（btcli 9.x）怎么办

先找到旧版是从哪里装的：

```bash
which -a btcli
```

**情况 1：路径里有 `uv/tools/bittensor-cli`**（用 `uv tool install bittensor-cli` 装的）

```bash
uv tool uninstall bittensor-cli
uv tool install bittensor
```

**情况 2：在某个 Python 环境里用 pip 装的**

顺序很重要：**先卸载旧包，再升级**。两个包都声明自己拥有 `btcli` 这个命令，顺序反了会出问题。

```bash
pip uninstall -y bittensor-cli bittensor-wallet
pip install -U bittensor
```

如果已经先升级、后卸载，`btcli` 命令可能会消失。重新装一次即可，不会丢数据：

```bash
pip install --force-reinstall --no-deps bittensor
```

**情况 3：requirements 文件里写死了旧版本**

把 `bittensor-cli`、`bittensor-wallet` 从 requirements 里删掉，把 `bittensor` 改成 `bittensor>=11`。写着 `bittensor<11` 或 `bittensor~=10` 的项目会继续停留在旧版，而且不会有任何提示。

## 5. 钱包和配置

- **钱包不用转换。** 11.x 仍然读 `~/.bittensor/wallets/`，文件格式相同，原来的钱包直接能用。用 `btcli wallet list` 确认。
- **配置文件换了位置。** 旧版的 `~/.bittensor/config.yml` 在 11.x 下会被忽略，并在每次运行时提示。新配置保存在 `~/.bittensor/btcli.json`，用下面的命令重新设置：

  ```bash
  btcli config set network finney
  btcli config set wallet camp
  btcli config get
  ```

  设置好以后，可以把旧的 `config.yml` 改名或删除。
- **环境变量改名**：`BT_SUBTENSOR_NETWORK` → `BT_NETWORK`，`BT_WALLET_NAME` → `BT_WALLET`。`BT_WALLET_HOTKEY`、`BT_WALLET_PATH` 不变。

## 6. 旧教程里的命令怎么改

v11 的规律：**所有查询是 `btcli query <名称>`，所有交易是 `btcli tx <名称>`**。`wallet`、`subnets`、`stake`、`weights` 这些常用命令组也还在。

**参数写法**

| 旧写法（9.x） | 新写法（11.x） |
|---|---|
| `--wallet.name camp` 或 `--wallet-name` | `-w camp` |
| `--wallet.hotkey default` | `-H default` |
| `--subtensor.network test`、`--chain` | `-n test` 或 `--network test`（也可以直接写 `ws://` 地址） |
| `--no-prompt` | `-y` |
| `--json-output` | `--json` |
| `--mev-protection` | `--mev-shield` |
| — | `--dry-run`（任何交易都可以先预览费用和结果，不提交） |

**常用命令**

| 要做的事 | 11.x 命令 |
|---|---|
| 查余额 | `btcli wallet balance <地址>` |
| 子网列表 / 概况 | `btcli subnets list`、`btcli subnets show 64`（编号直接写在后面，不再用 `--netuid`） |
| 元图 | `btcli query metagraph --netuid 64` |
| 注册价格 | `btcli query burn --netuid 64` |
| 新手保护期 | `btcli query immunity-period --netuid 64` |
| 是否开启 commit-reveal | `btcli query commit-reveal-enabled --netuid 64` |
| 注册矿工 / 验证者 | `btcli subnets register --netuid <编号>`（交易名为 `btcli tx burned-register`） |
| 我的 hotkey 注册在哪些子网 | `btcli wallet registrations` |
| 发布矿工端点 | `btcli tx serve-axon --netuid <编号> --ip <IP> --port <端口>` |
| 提交权重 | `btcli weights set --netuid <编号> --uids 0,1 --weights 0.6,0.4`（会自动处理 commit-reveal） |
| 查看全部查询 / 交易 | `btcli query --help`、`btcli tx --help` |
| 看懂报错 | `btcli explain <错误码>` |

旧版的简写（如 `w`、`s`、`st`）和下划线写法（如 `wallet new_hotkey`）还能用，但课程里统一用上表的写法。

**公开网络没有水龙头**：主网和测试网都不能用命令领测试币（会报 `FaucetDisabled`）。第二周我们用本地教学链，链上自带测试 TAO。

## 7. 写代码时要知道的变化（第 9–11 天）

如果你看的是旧版矿工或验证者教程，下面这些已经变了：

- **`bt.Axon`、`bt.Dendrite`、`bt.Synapse` 都没有了。** 矿工和验证者之间用普通 HTTP 通信，用 `bt.http_auth.sign` / `bt.http_auth.verify` 对请求做 hotkey 签名和校验。链上只保存矿工的 `ip:port`。详见 [Signed requests](https://www.bittensor.com/docs/guides/signed-requests)。
- **`bt.Subtensor` 名字没变，但方法全换了。** 读数据用分类方法，例如 `client.subnets.metagraph(netuid)`；交易统一写成 `client.execute(bt.SetWeights(...), wallet)`。
- **元图不再是一堆数组。** 现在是一个个节点记录，例如 `n.uid`、`n.incentive`、`n.validator_permit`、`n.axon`。
- **提交权重直接传小数。** 只看比例，归一化和整数转换由 SDK 完成；旧的 `weight_utils` 已删除。开启 commit-reveal 的子网，链会在 reveal 周期后自动解密生效，不用手动 reveal。
- **交易结果用错误码判断。** 看 `result.success` 和 `result.error.code`，不要匹配报错文字。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `btcli --version` 显示 9.x | 装的是 `bittensor-cli`，按第 4 节处理 |
| 每次运行都提示 legacy config | 旧的 `config.yml` 还在，按第 5 节用 `btcli config set` 重设后删掉旧文件 |
| `No such option: --wallet.name` | 旧参数写法，改成 `-w` |
| 质押报 `SlippageTooHigh` | 新版默认 5% 滑点保护。先用 `--dry-run` 看报价；确认后可调高 `--rate-tolerance` |
| 发布端点报 `InvalidIpAddress` | 链不接受 `127.0.0.1`，改用局域网 IP 或公网 IP |
| Windows 上装不上 | 不支持原生 Windows，用 WSL 2 |
